## اختلاف‌هایی که نباید ایجنت را به تغییر اشتباه ببرند

۱. README هنوز «full-screen on phones» دارد، ولی readme و رفتار تأییدشدهٔ موبایل پنجرهٔ شناور است. چارچوب رفتار شناور را تثبیت می‌کند؛ بازگشت به تمام‌صفحه مجاز نیست.
۲. توضیح loader در README هنوز از hand-over قدیمی صحبت می‌کند؛ کار تغییر نام این سازوکار را طبق تصمیم مالک حذف کرده. ساخت دوبارهٔ مهاجرت نام قبلی لازم نیست.
۳. «همه ماژول‌های اختیاری خاموش» کلی‌گویی مستندات است؛ registry برای History استثنا دارد. چارچوب به ایجنت اجازهٔ خاموش‌کردن خودکار History نمی‌دهد.
۴. README دربارهٔ logging عبارات opt-in و on-by-default دارد. منبع تشخیص باید تنظیمات/کد جاری و اعلام در چت باشد؛ تغییر سیاست حریم خصوصی بدون انتخاب مالک مجاز نیست.
۵. برخی roadmapها هنوز می‌گویند Live/Woo/Sitesync ساخته نشده؛ اکنون پایه‌هایشان موجود است. هر کمبود باید از HEAD و تست واقعی اثبات شود.
۶. `tests/README.md` دربارهٔ اجرا نشدن MySQL در یک ممیزی تاریخی صحبت می‌کند؛ CI موفق اخیر شاهد دیگری است. در عین حال Woo می‌تواند در integration چاپ SKIP کند؛ CI عمومی به‌تنهایی تأیید خرید واقعی یا HPOS نیست.
۷. roadmap از «قابلیت فراخوانی ابزار هنوز نیست» در نسخهٔ قدیمی می‌گوید؛ پیش از طراحی، provider و مسیر فعلی دوباره خوانده شوند. طرح registry مشترک از اسناد حفظ شده، ولی وجود آن ادعا نشده.
۸. لایسنس مارکت در نسخهٔ فعلی کلاس و build path دارد؛ توصیهٔ بسیار قدیمی «از صفر بساز» یا «اصلاً وجود ندارد» ملاک تغییر نیست. سازوکار موجود بررسی شود.

این اختلاف‌ها در این درخواست فقط ثبت شده‌اند؛ مستندات مخزن یا کد به‌صورت خودکار اصلاح نشده‌اند. اصلاح مرتبط می‌تواند در فاز صفر پیشنهاد یا بعداً صریحاً انتخاب شود.
