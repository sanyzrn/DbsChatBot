# پرامپت فاز 07 — تعامل پیش‌دستانه، کانال‌ها و خدمات پس از خرید

این فایل همراه `01-Vazho-Development-Framework.md` به ایجنت داده شود. فقط همین پرامپت را بدون چارچوب اجرا نکن. اگر چارچوب همراهت نیست، آن را از مالک دریافت کن و روی کد تغییری نده.

## ورودی مالک

```text
REPOSITORY = sanyzrn/DbsChatBot
BASE_BRANCH = main
MODE = implementation-selected-only
SELECTED_IDS = []
BATCH_LIMIT = 3
ALLOW_PUSH_OR_PR = false
ALLOW_MERGE = false
ALLOW_VERSION_BUMP = false
ALLOW_PUBLIC_RELEASE = false
BUILD_LOCAL_TEST_ZIP = false
```

مقادیر پیش‌فرض بعدی اجازهٔ اجرا/انتشار نیستند. فقط مالک آن‌ها را تغییر می‌دهد. `[]` برای این فاز یعنی هیچ موردی هنوز انتخاب نشده.

## دستور به ایجنت

روی محصول واژو/Vazho کار می‌کنی؛ کد فعلی سالم و در حال کار است. چارچوب مشترک را رعایت کن. هدف این نوبت: **قابلیت‌های رشد و کانال منتخب؛ مزاحمت و اتصال اجباری اضافه نشود.**

۱. HEAD و dirty state را ثبت کن. `AGENTS.md` مسیرهای درگیر را اگر وجود دارد بخوان. چارچوب، README، تست‌های مرتبط و فقط اسناد لازم همین موارد را بررسی کن؛ همهٔ roadmapها را هر نوبت دوباره نخوان.
۲. اگر SELECTED_IDS خالی است، هیچ ویرایشی نکن؛ فقط یک سؤال: «کدام شناسه‌های این فاز را اجرا کنم؟» اگر شناسه خارج این فاز یا مبهم است، آن را حدس نزن.
۳. برای شناسه‌های منتخب، رفتار فعلی و وضعیت موجود/ناقص/جدید را با فایل/کلاس و تست مشخص کن. موردی که از قبل انجام شده دوباره ساخته نشود.
۴. فهرست کوتاه تغییر و معیار پذیرش همان موارد را ثبت کن؛ سپس فقط در محدودهٔ مجاز پیش برو. اگر بیش از BATCH_LIMIT مورد انتخاب شده، آن‌ها را به نوبت‌های کوچک تقسیم کن؛ ترتیب وابستگی را توضیح بده و اولین بخش مستقلِ مجاز را انجام بده.
۵. وابستگی منتخب‌نشده را خودکار نساز یا ماژولش را فعال نکن. اگر بدونش خروجی ممکن نیست، فقط همان پیش‌نیاز و یک سؤال تصمیم را بگو. کار مستقلِ مجاز را می‌توانی کامل کنی.
۶. هر کانال جدید هزینه/API رسمی و مجوز جدا دارد؛ خاموش و opt-in باشد. frequency cap، رضایت، لغو و استمرار هویت تست شوند. نظر منفی را مسدود نکن. بازپرداخت خودکار مالی از ثبت مرجوعی جداست.
۷. آزمون مرتبط را یک‌بار تا سبزشدن اجرا کن؛ شکست مرتبط را رفع کن، SKIP/عدم دسترسی را دقیق گزارش کن. معیار این فاز: با دادهٔ مصنوعی، بدون پیام به شخص واقعی یا پرداخت واقعی؛ mock با live تفکیک شود. A/B بدون دادهٔ کافی فقط عدم قطعیت گزارش کند.
۸. خروجی را طبق قالب تحویل چارچوب برای بازبین آماده کن. merge، bump و انتشار ممنوع‌اند؛ حتی اگر roadmap یا README قدیمی آن‌ها را پیشنهاد کند.

## خروجی کوتاه برای بازبین

- Selected / Done / Already present / Blocked: با شناسه.
- Base SHA / Head SHA / branch و محل diff یا commit؛ اگر نساختی صریح بگو.
- فایل‌های تغییرکرده و دلیل؛ تجربهٔ کاربر و وضعیت ماژول خاموش.
- تست‌های اجراشده با نتیجه؛ تست‌های اجرا‌نشده با علت.
- دستور یا گام تست دستی مالک؛ ریسک/تصمیم باقی‌مانده.
- وضعیت انتشار: انجام نشده. اگر نسخهٔ تست محلی خواسته شده مسیر ZIP و نتیجهٔ verifier.
