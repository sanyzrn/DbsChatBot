# طراحی محدود رسید پاسخ — AR-01

وضعیت: **نسخهٔ اول در branch پیاده‌سازی شده؛ وضعیت آزمون/ادغام در STATUS.md و PR #44**. زیرمجموعهٔ محدود 04-04؛ تأیید این طراحی به‌معنی انتخاب تمام فاز چهار نیست.

## مسئله و هدف

بازدیدکننده و مدیر بتوانند بفهمند پاسخ از چه مسیری آمده و چه منابعی برای آن در دسترس بوده‌اند، بدون تبدیل «منبع بازیابی‌شده» به مهر تضمین صحت. استفادهٔ عادی چت باید ساده بماند.

نسخهٔ اول فقط provenance شفاف است: یک نشان کوتاه و بخش بازشوندهٔ «دربارهٔ این پاسخ». تاریخ بازبینی، گردش تأیید، تشخیص جامع تناقض، چرخهٔ FAQ و آزمایشگاه کیفیت در این نوبت طراحی/ساخت نمی‌شوند.

نمایش نشان برای هر مسیر باید در پیاده‌سازی با UX فعلی سازگار شود؛ source داخلی قرار نیست عیناً به مشتری نمایش داده شود.

## مرز ماژول و تنظیمات

پیشنهاد: ماژول اختیاری `answer_receipt`، پیش‌فرض خاموش، در دستهٔ knowledge؛ به AI provider اجباری وابسته نیست تا پاسخ bank-only هم کار کند. این نام در registry فعلی وجود ندارد و صرفاً شناسهٔ پیشنهادی نسخهٔ آینده است.

- یک کنترل اصلی روشن/خاموش در Modules؛ تنظیمات اضافی v1 نساز. توضیح کوتاه منفعت، نه متن فنی.
- خاموش: payload/نشان جدید تولید نشود؛ رفتار و گزینهٔ فعلی show_sources حفظ شود. هیچ فراخوانی مدل، embedding، خزش، job یا پنل جدا برای receipt ساخته نشود.
- روشن: فهرست موجود منابع با جزئیات رسید ادغام شود. اگر show_sources خاموش است، receipt حق افشای عنوان/URL منبع را ندارد؛ فقط مسیر عمومی پاسخ قابل نمایش است.
- به History وابسته نباشد. اگر History خاموش است، برای این ویژگی transcript یا ذخیرهٔ دائمی تازه ایجاد نشود.
- v1 هیچ درخواست تازهٔ AI ندارد؛ این با «همهٔ مکالمه بدون هزینه است» فرق دارد.

## قرارداد پیشنهادی داده؛ هنوز در کد وجود ندارد

فیلد اختیاری `receipt` در کنار source فعلی، با قرارداد نسخه‌دار:

```json
{
  "version": 1,
  "kind": "ai",
  "provenance": "retrieved_context",
  "generated_at": null,
  "reviewed_at": null,
  "sources": []
}
```

- kind از فهرست کنترل‌شدهٔ پاسخ واقعی؛ provenance وضعیت metadata را بگوید، نه امتیاز اعتماد.
- generated_at فقط زمان واقعی تولید؛ reviewed_at در v1 معمولاً null است. زمان ویرایش/همگام‌سازی مدرکِ بازبینی انسانی نیست و جای reviewed_at قرار نگیرد.
- هر source عمومی فقط عنوان و URL مجاز و در صورت وجود نوع «بازیابی‌شده/وب». شناسهٔ داخلی، متن خصوصی، مسیر فایل، query شامل secret و دادهٔ شخصی صادر نشود.
- metadata سمت سرور ساخته و در مرز خروجی allowlist/escape شود. مرورگر و متن مدل اجازه ندارند وضعیت تأیید/بازبینی بسازند.
- منابع bank از رکورد bank همان پاسخ گرفته شوند؛ از static last_sources باقیماندهٔ فراخوانی قبلی استفاده نشود.
- cache جدید: متن و snapshot منشأ پاسخ کنار هم و بدون PII/secret ذخیره شوند. قدیمیِ رشته‌ای خواندنی باقی بماند؛ در برخورد با آن unknown نشان بده، migration وسیع لازم نیست.
- اگر مدرک منبع بعداً خصوصی/حذف شد یا حق دسترسی از بین رفت، لینک/عنوان نباید از cache افشا شود؛ در زمان نمایش دسترسی دوباره ارزیابی شود، بدون انتساب منابع فعلی به پاسخ قدیمی.
- نسخهٔ اول به تغییر جدول DB نیاز قطعی ندارد؛ قبل از schema migration، envelope و cache موجود بررسی شوند. حذف داده/پرکردن مصنوعی تاریخ ممنوع.

## انتقال، ماندگاری و UI

- REST، legacy AJAX، preview و SSE final باید هم‌معنا باشند؛ receipt بعد از پایان پاسخ استریم نمایش یابد، نه با هر token.
- هنگام History/reopen اگر ساختار فعلی metadata نگه نمی‌دارد، رسید را برای پاسخ قدیمی بازسازی نکن؛ پیام قبلی بدون رسید یا با وضعیت ناموجود بماند. افزودن ذخیرهٔ تاریخچه تصمیم جداست.
- v1 نمایش وب/preview؛ پیام‌رسان‌های موجود نباید بشکنند یا JSON خام ببینند. پشتیبانی کامل receipt کانال‌ها خارج دامنه است.
- RTL، لینک انگلیسی، متن بلند، keyboard/focus و موبایل شناور تست شوند؛ یک ردیف بازشونده با نام قابل فهم، بدون نمرهٔ سبز گمراه‌کننده.

## محدودیت‌های روشن نسخهٔ اول

- منابع اسناد وارداتی که به صفحهٔ عمومیِ قابل احراز همین سایت نگاشت نمی‌شوند، عنوان/لینک عمومی نمی‌گیرند؛ برای citation وب provider فقط URL عمومیِ امن و بدون query/fragment پذیرفته می‌شود. این محافظه‌کاری ممکن است منابع مجاز بیشتری را پنهان کند.
- برای noindex محلی، تنظیم شناخته‌شدهٔ Yoast و Rank Math و فهرست استثنای Sitesync بررسی می‌شود؛ انطباق با تمام افزونه‌های کنترل دسترسی/سئو ادعا نشده است.
- metadata به تاریخچه افزوده نمی‌شود؛ پس از بازکردن گفتگو از سابقه، رسید قبلی بازسازی نمی‌شود.
- آزمون مرورگرِ component جای آزمون کامل روی وردپرس واقعی و سرویس live را نمی‌گیرد.
