# واژو / Vazho — فازبندی جامع و فهرست انتخاب توسعه

تاریخ: ۲ نوامبر ۲۰۲۶ | مخزن: `sanyzrn/DbsChatBot` | مبنای نسخه: 1.7.9

**وضعیت: فقط برنامه‌ریزی؛ هیچ ردیف این سند مجوز اجرا نیست.** سعید می‌تواند از هر فاز فقط چند مورد را انتخاب کند، بقیه را عقب بیندازد یا حذف کند. ترتیب فازها منطقی است، نه تعهد زمانی یا الزام به اجرای کامل فاز قبل.

## مبنا و حدود اطمینان

- ورودی‌ها: نقشهٔ توسعهٔ قبلی، هر سه فایل گزارش اصلی داخل ZIP، گفتگوهای قابل مشاهده و بازیابی نکات گفتگوهای همین پروژه.
- تغییر نام به واژو/Vazho در PR #42 مرج و تست‌ها تأیید شده است؛ برای این تغییر ریلیز جدید منتشر نشده.
- وضعیت امکانات دیگر عمدتاً از نقشهٔ قبلی و گزارش کارها آمده است؛ این درخواست ممیزی تازهٔ همهٔ کد و نصب واقعی نیست. عبارت «ارتقای موجود» به‌معنی تأیید سلامت کامل نیست.
- متن/تصویر اصلی داوری ده‌بندی در پیوست فعلی نیست؛ جدول داوری از خلاصهٔ بازیابی‌شدهٔ گفتگو تنظیم شده، نه نقل‌قول مستقیم از مارکت. شمارهٔ ۸ مزیت رقابتی و ۹ API آزمایشی در بازیابی مشخص شد؛ در صورت تفاوت با تصویر اصلی، اصل داوری مقدم است.
- گزارش سومِ داخل ZIP بعد از بخش ۴ پایان می‌یابد، با اینکه به بخش‌های بعدی ارجاع می‌دهد؛ برای قسمت‌های ناموجود محتوایی ساخته نشده است.
- اعداد فروش، قیمت، ادعاهای «بی‌رقیب»، تضمین دقت/درآمد و زمان‌بندی ماهانهٔ گزارش‌ها مبنای تعهد نیستند. این سند ایده‌ها را استخراج می‌کند، نه اینکه ادعاهای بازار یا حقوقی آن گزارش‌ها را دوباره تأیید کند.
- «همهٔ موارد» در این سند یعنی درخواست‌های مرتبط با خود افزونه و پیشنهادهای محصولی/فنی گزارش‌ها؛ پیشنهادهای نامرتبطِ بازیابی‌شده از پروژه‌های Nex، NexaHR یا وب‌سایت به این پروژه منتقل نشده‌اند.

## روش انتخاب

ستون «انتخاب سعید» عمداً خالی است: `اجرا`، `بعداً`، `حذف` یا `نیاز به توضیح` بنویس. نمونه: **01-04 اجرا؛ 02-07 بعداً؛ 03-02 نیاز به توضیح**. انتخاب یک ردیف به‌معنی انتخاب تمام فاز نیست. بعد از انتخاب، فقط برای همان موارد دامنه، وابستگی، معیار پذیرش و برآورد تعیین می‌شود.

## نکات اصلاح‌شده هنگام جمع‌بندی گزارش‌ها

- «برآورد هزینه قبل از ایندکس» جایگزین وعدهٔ هزینهٔ دقیق در همهٔ مدل‌ها شده است.
- Shadow DOM گزینهٔ قابل ارزیابی است؛ وعدهٔ بی‌تداخل‌بودن قطعی داده نشده.
- تشخیص تصویر و خرابی، نظر کمکی است؛ تأیید سازگاری یا استرداد مالی خودکار از آن نتیجه گرفته نمی‌شود.
- در نظرخواهی پس از خرید، شکایت به پشتیبانی می‌رود اما امکان درج نظر منفی عمومی مسدود نمی‌شود.
- نبودن یک قابلیت در بررسی رقبا، اثبات «اولین/تنها» بودن واژو نیست.
- اتصال API آزمایشی داور با ساخت سرویس اعتبار ابری برای همهٔ مشتریان یکی نیست.
- امکان چندکانالهٔ نامحدود، اپ موبایل همراه یا White Label رایگان تصمیم تجاری است؛ از گزارش رقبا به‌عنوان تعهد واژو منتقل نشده.

## معیار تحویل هر موردی که بعداً انتخاب می‌شود

سناریوی کاربر و محدودهٔ تغییر → بررسی قابلیت مشابه موجود → UX دسکتاپ/موبایل/RTL → رفتار خطا و مصرف → دسترسی/حریم خصوصی مرتبط → آزمون متناسب با تغییر → مستند و دموی واقعی. تست اضافهٔ نامرتبط یا بازنویسی بخش سالم، هدف این برنامه نیست.

**اقدام بعدی فقط انتخاب شناسه‌ها توسط سعید است؛ این سند هیچ اجرای خودکاری را آغاز نمی‌کند.**
